## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a running script's logs, per-call outcomes, and status changes stream live to the application while it runs — and every SDK call also lands in the audit trail.

<objective>
Build the script event stream (D-04) and per-call outcome reporting (D-05) on the Phase 7 pattern, and wire every SDK call into the existing audit pipeline through one new exported seam (SCRP-05).

Purpose: SCRP-05 is the requirement that makes a sandbox usable rather than merely safe. Without a live, ordered, non-coalescing stream, a script is a black box whose failure mode is "nothing happened".
Output: `internal/script/events.go`, the `api.PublishMutationEvent` seam, the SSE type tag, and the ordered Wails script queue.

**Flagged assumption to record in the SUMMARY (SCRP-05, unclassified edge probe — surfaced, not silently dropped):** the spec-less probe classified SCRP-05's edge category as `unclassified`, so no automated edge criterion was derivable. The planner's judgment is that SCRP-05's operative edge is *terminal-event completeness*: the failure that actually hurts a user is a run that ends without any event saying so, leaving the panel stuck on "Running" forever. The chosen mitigation is an unconditional terminal event on every termination path, asserted by a table test that enumerates every termination cause. If a reviewer disagrees that this is SCRP-05's operative edge, raise it before 08-10 builds the debug panel on top of this contract.
</objective>
