## Phase Goal

**As an** integrator, **I want to** inspect and control every public GOLC capability through a secure, versioned, revision-aware HTTP API, **so that** external programs behave exactly like the desktop application.

<objective>
Fold in the two non-blocking findings that bear directly on mutation correctness: WR-01 (the Idempotency-Key store is keyed on the raw client string alone, so two actors sharing a key string receive each other's cached responses) and IN-02 (list-valued fields are comma-joined into CLI arguments with no escaping and no boundary rejection, so a value containing a comma silently splits).

Purpose: neither is a Success Criterion blocker, and 07-VERIFICATION.md marked API-04 SATISFIED for the wired route — but both are documented latent defects whose blast radius grows with every route EXTN-05 adds. Fixing them now, while exactly one mutating route exists, is a handful of lines; fixing them after breadth lands is a migration. This is a deliberate fold-in, not scope creep: both were surfaced by this phase's own code review and neither is being deferred silently.
Output: a composite `(actor, route, key)` idempotency key, a single shared list-value validator wired into both the single-mutation and batch translators, tests for both, and a drift-clean regenerated contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-chosen Idempotency-Key → server-side response cache | An opaque string chosen by one client selects which stored response is returned; without scoping, that string spans actors |
| client JSON list field → comma-joined CLI argument | A structured JSON array is flattened into a delimited string for a downstream process that re-splits it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-25 | Information Disclosure / Spoofing | `idempotencyStore` keyed on the raw client string | high | mitigate | Composite comparable `(actor, route, key)` struct key means a stored response is only ever returned to the credential and route that produced it; pinned by TestIdempotencyKeyScopedByActor. Low exploitability today (one route, non-sensitive body), high once EXTN-05 wires mutating routes — fixed while it is cheap. |
| T-07-26 | Tampering | list-valued fields flattened into a comma-delimited CLI argument | medium | mitigate | `validateListValues` refuses any element containing the reserved delimiter with a typed 400 before `strings.Join` runs, on both the single and batch paths; the contract documents the restriction. |
| T-07-26b | Elevation of Privilege | delimiter injection reaching a privilege-bearing list | medium | mitigate | The same helper is applied to the `scopes` list in 07-14, closing the one delimiter-joined field where a split value could widen a credential rather than merely mis-shape a pool. Recorded here so the pair is not separated. |
| T-07-27 | Denial of Service | idempotency map growth under a now-wider key tuple | low | accept | Entries still expire on read past their TTL, per-key `RateLimitMiddleware` bounds insert rate, and the store is per-daemon-run in-memory by design; a durable, actively-evicting store remains documented future hardening, unchanged by this plan. |

No package-manager installs (npm/pip/cargo) occur in this plan, so no supply-chain legitimacy checkpoint (T-{phase}-SC) applies.

Canon-referral breadcrumb: generic argument/command injection is canon and is already structurally owned by this package's Executor seam (no shell is ever invoked; args are passed as an argv slice) plus `/gsd-secure-phase` — the delimiter rule above is the bespoke, encoding-specific half and is the only piece minted as a prohibition.
</threat_model>
