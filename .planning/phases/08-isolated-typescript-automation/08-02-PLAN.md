## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section — the ROADMAP goal is not in user-story form and no story was invented.

**This plan's slice:** after this plan, a contributor running `mage Bootstrap` on a clean checkout gets a pinned, checksum-verified Deno runtime provisioned exactly like Go, Node, and Mage already are — the runtime every later execution slice spawns.

<objective>
Pin Deno into the existing immutable toolchain-pin discipline and provision it through `internal/bootstrap`, plus the one resolver (`internal/script.ResolveDenoExecutable`) every later plan uses instead of a PATH lookup.

Purpose: SCRP-03's "no ambient filesystem, network, environment, subprocess, or native-code permissions" claim is only defensible if the runtime enforcing it is itself a byte-verified, allowlist-sourced binary — not whatever `deno` happens to be on the machine.
Output: `[toolchain.deno]` in config/toolchain.toml, its strict-spec keys, its bootstrap layout, and `internal/script/toolchain.go`.
</objective>

## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain "Supply-chain injection" row and the existing D-01/T-01-SC acquisition-allowlist contract in config/toolchain.toml's header.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-SC | Tampering | Deno archive acquisition | high | mitigate | Archive bytes are SHA-256 verified against a committed pin before extraction; the URL must match the committed `official_host`/`official_path_prefix` allowlist consumed by `OfficialSourcePolicy`. The pinned hash is byte-verified against the official per-asset checksum during this task, not copied from a mirror. Deno is a GitHub-release archive pin (the same seam as Go/Node/Mage), not an npm/PyPI/crates install, so the npm-oriented package-legitimacy checkpoint does not apply here — it applies to `monaco-editor` in 08-11. |
| T-08-06 | Spoofing | executable resolution | high | mitigate | `script.ResolveDenoExecutable` is the only source of the Deno path and resolves strictly under `.tools/toolchains/deno/`; no `exec.LookPath`, no env-var override, no caller-supplied path — so an attacker-planted `deno.exe` earlier on `PATH` can never become the sandbox runtime. |
| T-08-07 | Tampering | hand-edited config/toolchain.toml | medium | mitigate | Strict spec keys with anchored URL/SHA patterns and `AllowedValues` host/prefix constraints fail resolution with a stable diagnostic before any fetch, matching the existing go/node/mage keys. |
</threat_model>
