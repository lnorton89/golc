## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a user writes GOLC automation with real autocomplete and live type errors against the generated SDK, in an editor that looks like the rest of GOLC rather than like VS Code.

<objective>
Deliver D-15: replace 08-04's placeholder textarea with a Monaco editor running the TypeScript language service against the generated `golc.d.ts`, reconciled to the Paper/Ink design system.

Purpose: D-15 is what makes a capability-limited SDK usable — an author who cannot discover the SDK by autocomplete will write scripts by guessing, and the sandbox's job becomes rejecting guesses instead of enabling work.
Output: `ScriptEditor.tsx`, `monacoTheme.ts`, the pinned `monaco-editor` dependency, and the `.d.ts` delivery path.
</objective>

  <name>Task 1: Confirm the exact monaco-editor version before first install</name>
  <what-built>
Nothing yet — this gate precedes the first `npm install monaco-editor`.

08-RESEARCH.md's Package Legitimacy Audit recorded **SUS** for `monaco-editor` on the "too-new" heuristic: its latest tag (0.56.0) was published five days before the research ran. The audit's own read is that this is a heuristic false positive — Microsoft ships `monaco-editor` on a fast cadence, it has ~7.9M weekly downloads, and its source repo is `github.com/microsoft/monaco-editor` — but a recorded SUS verdict must be honoured, not argued away. The audit's instruction is to pin an older, previously-stable minor rather than the bleeding-edge one, and to have a human confirm the exact pinned version before first install.

Before presenting this checkpoint, gather and show:
  1. `npm view monaco-editor versions --json | tail -20` — the recent version list.
  2. `npm view monaco-editor@<candidate> dist.tarball dist.integrity time` for the proposed pin.
  3. The `repository` field from `npm view monaco-editor repository`, confirming it is `github.com/microsoft/monaco-editor`.
  4. The proposed pinned version and why it is the previously-stable minor rather than the newest release.
  </what-built>

1. Confirm the printed `repository` is `github.com/microsoft/monaco-editor` and not a lookalike.

3. Confirm the weekly download count is in the millions (consistent with the de facto standard editor, inconsistent with a slopsquat).
4. Confirm the proposed pin is NOT the newest release.
