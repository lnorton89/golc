# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately bypassed, same rationale as Phase 6 |
| Preset | not applicable |
| Component library | none — plain HTML controls under component-scoped CSS Modules, reusing `frontend/src/components/primitives/*` (Button, Panel, PanelHeader, Toolbar, ScrollRegion, Chip, Field, ListRow) |
| Editor widget | `monaco-editor` (npm) — a new, single-purpose dependency for D-15's live TypeScript language service; not a general component library |
| Icon library | none |
| Font | Archivo (UI text/labels/headings) + JetBrains Mono (technical/code) |

**Why no shadcn (unchanged from Phase 6):** `.planning/research/STACK.md`'s instruction to avoid a theme framework that dictates console density still applies; nothing in this phase changes that call.

**Component library correction (grounded in the actual codebase, not the aspirational Phase 6 UI-SPEC entry):** 06-UI-SPEC.md declared Radix UI Primitives + `lucide-react` as the component/icon libraries, but neither is installed or imported anywhere in `frontend/src` as of Phase 7 (`grep -rl "@radix-ui\|lucide-react" src` returns nothing). The actually-delivered pattern is plain HTML controls (`<button>`, `<input>`, `<select>`) styled through CSS Modules, and a hand-rolled backdrop+`role="dialog"` overlay for the one existing modal (`frontend/src/shell/HelpOverlay.tsx`, whose own header comment explains why Radix wasn't worth adding for one static dialog). Phase 8's Run/Debug launch dialog (D-07) should follow `HelpOverlay.tsx`'s exact pattern — backdrop click + Escape to close, focus moved to the dialog on open, `role="dialog" aria-modal="true"` — not introduce Radix. Icon usage is likewise zero across the whole frontend; Phase 8 continues text/label-first affordances. Monaco's own built-in glyph-margin breakpoint dot is Monaco's native rendering, not a GOLC icon dependency.

**Monaco chrome reconciliation (new territory this phase introduces):** Monaco ships VS Code's dark theme and toolbar chrome by default; both must be reconciled to Paper/Ink, not left at Monaco defaults:
- Define two `monaco.editor.defineTheme` registrations (`golc-paper-ink-light`, `golc-paper-ink-dark`) that map Monaco's token/UI colors onto the existing CSS custom properties (`--page`, `--panel`, `--ink`, `--text`, `--muted`, `--line`, `--accent`, `--status-revoked`), and switch between them on the same `prefers-color-scheme` signal `index.css` already keys off — Monaco does not auto-follow the media query, so this must be driven programmatically.
- Editor `fontFamily: "JetBrains Mono"`, `fontSize: 14`, `lineHeight: 21` (14 × 1.5, matching the declared Technical readout row in Typography below) — do not leave Monaco's own default line-height (~19px) unreconciled against the rest of the technical-readout rhythm.
- `minimap.enabled: false` — a decorative minimap contradicts the dense, non-decorative console direction (`.planning/sketches/SKILL.md`'s "compact ... spacing" and "prefer selection-driven detail ... over a page-length dashboard").
- `glyphMargin: true`, `lineNumbers: "on"` — required for the D-01/D-02 breakpoint gutter.
- Monaco's own command palette / built-in toolbar stays hidden; Run/Debug/Stop/Validate are GOLC `Button` primitives rendered in the workspace `Toolbar` action slot (see Copywriting Contract), never Monaco's native UI.
- Monaco's internal scrolling is acceptable as-is — it is already a bounded panel, consistent with `application-shell-navigation.md`'s "all scrolling occurs inside bounded panels" rule.
- `monaco-editor` is flagged **SUS** by `08-RESEARCH.md`'s Package Legitimacy Audit (too-new-version heuristic) — the planner must add a `checkpoint:human-verify` task naming the exact pinned version before the first `npm install`. This is a supply-chain gate, not a visual-design open question, and is noted here only so the plan doesn't drop it.

## Spacing Scale

Declared values (multiples of 4), identical to the project-wide scale Phase 6 established:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free inline gaps, log-row internal spacing |
| sm | 8px | Compact element spacing, debug-panel row padding, capability-profile field gaps |
| md | 16px | Default element spacing, panel internal padding |
| lg | 24px | Section padding (Run/Debug dialog body) |
| xl | 32px | Layout gaps between major panels (script library ↔ editor ↔ inspector) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing; also the safety-cluster touch target (unchanged, unrelated to this phase) |

Exceptions:
- **Monaco editor internal metrics (gutter width, line height, glyph-margin click target):** governed by Monaco's own layout engine per the Design System section above, not by this scale — documented as a locked chrome region, the same way Phase 6 treated the live status bar.
- **Run / Debug / Stop / Validate buttons:** standard 32px `Button` height (existing `Button.module.css`) — deliberately **not** the 64px safety-cluster touch target. Per D-10, per-script Stop must read as a normal, lightweight action, visually distinct from Phase 6's 64px hold-to-confirm Stop/Release-All control — using the same button scale as every other secondary/destructive action in the app is itself the mechanism that keeps the two apart.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Archivo Regular (400) | 1.5 |
| Label | 14px | Archivo Regular (400) | 1.4 |
| Heading | 20px | Archivo Semibold (600) | 1.2 |
| Display | 28px | Archivo Semibold (600) | 1.2 |
| Technical readout | 14px | JetBrains Mono Regular (400) | 1.4 |

Declared weight set: **Regular (400) + Semibold (600)** — unchanged from Phase 6, exactly two weights.

**Code/editor content reuses the Technical readout row, not a new size.** Monaco's editor buffer, the live log/diagnostics stream (D-04), individual command-outcome entries (D-05), source-mapped stack traces (D-03), and diagnostic/error codes all render at 14px JetBrains Mono Regular — the same declared size and weight as every other technical readout in the app (BPM, MIDI Note/CC, `GOLC_*` codes). Monaco's own internal `lineHeight` is set to 21px (14 × 1.5) so the editor's rhythm matches the rest of the technical-readout scale rather than introducing a fifth undeclared size. No new font size is introduced by this phase — the table above stays at its Phase 6 four distinct sizes (14/16/20/28).

Script names, capability-profile labels, and dialog copy use the existing Label/Body/Heading rows exactly as Phase 6 defined them.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#E4E0D8` light / `#131419` dark (`--page`) | Application canvas background, unchanged |
| Secondary (30%) | `#F4F1EB` light / `#1E2027` dark (`--panel`) | Script library rows, editor chrome (via Monaco theme mapping), debug panel background, Run/Debug dialog surface |
| Accent (10%) | `#1B44D9` Signal Blue (`--accent`) | Run button (filled, primary), the currently-selected script in the library list, focus rings, Monaco's active-line/selection highlight (mapped through the custom theme) |
| Destructive | `#E23A2E` (`--status-revoked`) | Stop Script button (destructive `Button` variant), Delete Script confirmation, terminated/crashed status chips |

Accent reserved for: the Run button (filled), the selected script row in the library, focus rings, and Monaco's selection/active-line highlight. **Debug is deliberately not accent-colored** — it renders as the existing neutral `secondary` `Button` variant (gray border, `--panel` background, `--ink` text). Pairing a filled Signal Blue "Run" against a neutral bordered "Debug" is the mechanism that satisfies CONTEXT.md's "visually distinguish Run vs Debug as two distinct launch actions" requirement without introducing a second accent color — reuses the `Button` primitive's existing primary/secondary contrast exactly as already built.

### Status Vocabulary (semantic, not part of the 60/30/10 split)

Reused directly from the existing six-color system (`index.css`); Phase 8 maps script run states onto it rather than inventing new state colors:

| Status | Value | Phase 8 usage |
|--------|-------|----------------|
| live | `#1B44D9` | "Running" status chip while a script is executing (Run or Debug mode) |
| armed | `#C8A24B` | "Paused at breakpoint" status chip and the current-execution-line highlight in the editor gutter (Debug mode only) |
| revoked | `#E23A2E` | "Terminated" / "Crashed" status chips (deadline/rate/resource/capability-scope violation, D-08; unhandled exception, D-03); also the breakpoint-set gutter dot (conventional red-dot-for-breakpoint across every mainstream debugger — spatially separate from the terminated/crashed status chip, so no ambiguity) |
| offline | `#8A887F` | Script host / daemon unreachable |
| frame-lock | `#5AC26A` | Not used by this phase (Art-Net-specific) |
| blackout | `#17181C` | Not used by this phase (global safety-specific) |

| Secondary CTA (script launch) | "Debug" |

| Advanced/custom field labels | "Deadline (seconds)", "Rate limit (calls/sec)", "Memory limit (MB)", "CPU cap (%)" |
| Validation error summary | "This script has {N} error(s). Fix them before running." |
| Error state — deadline/rate/resource termination (D-08) | "Terminated: {limit name} exceeded ({limit value}). Increase the limit in this script's profile if this is expected." |
| Error state — capability-scope violation | "Terminated: this script tried to call {command} outside its assigned {scope} capability." |
| Error state — crash (D-03) | "Script crashed: {error summary}" with an expandable, full source-mapped stack trace below |
| Error state — script host unreachable | "Can't reach the script host. GOLC will try to reconnect automatically." |
| Transient state — stopping (D-11) | "Stopping — finishing in-flight commands…" |
| Stopped/terminated banner (D-12) | "Stopped: {reason}" — remains visible with "Dismiss" and "Run Again" actions until the user acts; body copy "This script won't restart automatically — run it again when you're ready" (D-13) |
| Debug session — paused | "Paused at breakpoint — line {N}" with Continue / Step Over / Step Into / Step Out controls (conventional debugger vocabulary, matching the "real debugger" decision D-01) |
| Command outcome entry (D-05) | "{sdk.method}(...) → OK ({duration}ms)" success; "{sdk.method}(...) → ERROR: {message}" failure |
| Destructive confirmation — Delete Script | "Delete Script: This permanently removes {script name} and its saved capability profile from this show. This can't be undone." |

> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 15 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Script library (list-collection, D-16) | ✅ covered | Renders "No scripts yet" heading + body and a "New Script" CTA (see Copywriting Contract). |
| empty | Debug/log panel before first run (list-collection, D-04/D-05) | ✅ covered | Renders the "Run or Debug this script..." placeholder copy until the first log line or command outcome arrives. |
| loading | Script library / editor on initial daemon connect (list-collection, form) | 🧪 backstop | A skeleton/dim placeholder is expected while the host completes its first script-list fetch, matching Phase 6's identical unresolved skeleton item; exact treatment left to implementation. |
| loading | Run/Debug dialog submit (form, D-07) | ✅ covered | The dialog's Run/Start Debugging button disables and shows a busy state while the subprocess spawn is in flight; the dialog does not close until spawn succeeds or fails. |
| error | Script editor — validation failure (form, SCRP-01) | ✅ covered | Renders the "{N} error(s)" summary copy plus inline Monaco diagnostics; Run/Debug remain disabled until validation passes. |
| error | Debug/log panel — deadline/rate/resource termination (list-collection, D-08) | ✅ covered | Renders the limit-exceeded termination copy (see Copywriting Contract) as the terminal log/status entry. |
| error | Debug/log panel — capability-scope violation | ✅ covered | Renders the scope-violation termination copy; treated with the same immediate-hard-termination severity as D-08 per RESEARCH.md Assumption A2. |
| error | Debug/log panel — crash (list-collection, D-03) | ✅ covered | Renders the crash summary plus an expandable full source-mapped stack trace. |
| error | Script library / editor — script host unreachable (list-collection, form) | ✅ covered | Renders the host-unreachable copy; Stop Script and the global safety cluster remain reachable regardless (D-10/D-11 unaffected by host-connectivity UI state). |
| populated | Script library (list-collection, D-16) | ✅ covered | Each row shows script name, last-run status chip (status vocabulary), and assigned capability profile summary. |
| populated | Debug/log panel while running (list-collection, D-04/D-05) | ✅ covered | Live-streaming log lines and individual command-outcome entries render in arrival order, each with timestamp, source location, and outcome. |
| partial | Run/Debug dialog — capability profile with some fields left at preset defaults (form, D-07) | ✅ covered | Every field is always pre-filled from the saved profile (never blank) and independently editable; there is no unfilled/partial dialog state to design for. |
| overflow | Debug/log panel, long-running script (list-collection) | 🧪 backstop | Panel scrolls within its bounded region rather than growing the workspace; exact row-count/retention-before-scroll-truncation threshold not locked — verify against a representative long run during implementation. |
| overflow | Stack trace display (static-content, D-03) | ✅ covered | Renders collapsed by default behind "Script crashed: {summary}" and expands within the bounded panel via `ScrollRegion`, never growing the workspace. |
| overflow | Script name — library row and editor Toolbar title (nav, static-content) | ✅ covered | Truncates with ellipsis at the row/title's fixed width, full name on hover/tooltip — same uniform rule Phase 6 already applies to operator-surface and scene names. |
| zero-one-many | Script library (list-collection, D-16) | ✅ covered | 0 = empty state; 1 = singular "1 script"; many = plural count, identical row layout throughout. |
| zero-one-many | Breakpoint gutter markers (list-collection, D-01) | ✅ covered | 0 breakpoints = plain gutter; 1 or many = each renders an identical red dot glyph, no special-casing by count. |
| long-text | Command outcome / log entry messages (static-content, D-04/D-05) | 🧪 backstop | Long SDK-call arguments or error messages wrap within the bounded debug panel rather than overflowing it; exact wrap-vs-truncate threshold not locked — verify against representative long payloads during implementation. |
