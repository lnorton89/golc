## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a user sets a breakpoint by clicking the gutter, launches Debug, watches execution stop on that line, and steps through their script — the visible half of D-01's real debugger.

<objective>
Deliver the debugger's user interface: the glyph-margin breakpoint gutter, the current-execution-line highlight, and the four step controls, all driven by the backend's script events (D-01, D-03's clickable trace frames; SCRP-01's debug verb, SCRP-05's source locations).

Purpose: 08-09 built a real debugger the user cannot yet reach. This plan is the last step that makes D-01's deliberate departure from the lighter-weight option actually pay off for the author.
Output: the extended `ScriptEditor` and `ScriptDebugPanel`.
</objective>

## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain "Inspector/debug channel exposure" row.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-52 | Tampering | breakpoint line input | medium | mitigate | Breakpoint lines are validated backend-side against the script's actual line count (08-09 Task 3, `GOLC_SCRIPT_BREAKPOINT_INVALID`); the frontend's gutter is a convenience producer, never the validation authority. Shim-offset correction stays backend-side so the client never computes a position into the injected shim. |
| T-08-40 | Information Disclosure | inspector exposure | high | mitigate | The frontend calls named step routes only; it never receives an inspector port, WebSocket URL, or raw CDP frame, and no bridge method exposes one. The Go daemon remains the sole CDP client. |
| T-08-53 | Spoofing | optimistic paused state | medium | mitigate | Paused state is derived only from backend events, never set optimistically on click, so the UI can never claim a script is paused or resumed when the process is not — which would otherwise mislead a user into thinking a live show is safely stopped. |
| T-08-41 | Elevation of Privilege | debugger as a limit bypass | high | mitigate | The UI offers no affordance to extend a deadline or suspend a limit while paused; 08-09's backend already terminates a paused run past its deadline, and Stop Script remains a single click on a paused run. |
</threat_model>
