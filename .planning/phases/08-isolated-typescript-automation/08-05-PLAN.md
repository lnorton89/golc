## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a saved script actually runs — in a fresh, zero-permission Deno process that reaches GOLC only through the generated typed SDK over its own stdio.

<objective>
Build `internal/script`'s execution core: the newline-delimited-JSON session protocol, the zero-permission Deno host, and the `script run` CLI route that drives it (SCRP-01 run verb, SCRP-02 SDK-only access, SCRP-03 no ambient permissions).

Purpose: this is the plan the phase's central safety claim rests on. Every guarantee about what a script cannot do is either enforced here at the OS-process boundary or it is not enforced at all.
Output: `protocol.go`, `host.go`, `session.go` in `internal/script`, and `internal/command/scriptrun.go`.

**Planner scope call — surfaced, not silently defaulted (08-RESEARCH.md Open Question 1):** v1 supports **at most one active script run at a time**, globally. A second run request is rejected, not queued. Rationale: it makes D-10's "Stop targets one script" unambiguous, keeps the event stream single-writer, and matches the MVP slice. The subprocess-per-run architecture supports concurrency later with no redesign — every run already carries a distinct run id on every frame and every event, so lifting the restriction is additive. If the user wants concurrent runs in v1, raise it before 08-06 builds Stop on top of this assumption.
</objective>

  - `func (h *Host) Run(ctx context.Context, script show.Script, mode LaunchMode) (RunOutcome, error)`:
    1. Take the single-run lock; if a run is active return `GOLC_SCRIPT_RUN_ACTIVE`.
    2. Mint a UUIDv7 `RunID`.
    3. `os.MkdirTemp` a per-run directory; write `<runid>.ts` containing the generated `golc-runtime.ts` shim followed by the user's `Source`. Because the SDK is an ambient global (08-03), the user source needs no import line and none is injected.

    5. Start, then run two goroutines: a stdout frame-reader loop dispatching each frame, and a stderr reader appending to a `boundedBuffer` copied verbatim from `process.go`'s implementation, every line passed through `security.Redact` before it is stored.
    6. On a `cmd-call` frame: look the method up in `scriptsdk.RegisteredSDKMethods()`; unknown → `cmd-result` with `GOLC_SCRIPT_METHOD_UNKNOWN` and no Executor call. Known → build the argv for its route from the frame's `Params` and call `h.cfg.Executor.Execute`, then write a `cmd-result` frame carrying the exit code, stdout, and stderr. Record a `CallOutcome{Method, Route, DurationMS, Ok, Code, Message}` for every call — this is D-05's per-call record, consumed by 08-08's live panel and audit integration.
    7. Capability enforcement (D-06/D-08) is deliberately **not** in this task; 08-06 inserts it at the single point between the method lookup and the Executor call. Leave a clearly named `enforce` seam there so 08-06 fills one function rather than restructuring the loop.
    8. On child exit, drain remaining frames, remove the temp directory, release the lock, and return the outcome.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon → Deno child | The daemon spawns an untrusted-code-hosting OS process. |
| Deno child → daemon (stdio) | Every byte the child writes is attacker-controlled from the daemon's perspective. |
| child stdio → audit/logs/events | Captured output flows onward to durable and user-visible surfaces. |

## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain "Sandbox escape via native code/FFI or unexpected subprocess spawn", "Supply-chain injection via script import statements", and "Sensitive data leakage through captured script stdout/stderr" rows.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-15 | Elevation of Privilege | Deno permission surface | high | mitigate | Zero permission flags for every run, enforced by `buildDenoArgs` being the single composition site plus `TestDenoCommandLineHasNoAllowFlags` iterating every scope × preset × launch mode against `forbiddenDenoArgPrefixes`. FFI and subprocess spawn are therefore denied by the runtime itself, not by convention. |
| T-08-16 | Elevation of Privilege | ambient environment | high | mitigate | `cmd.Env` is an explicit slice; `os.Environ()` is never used, so no daemon secret, token, or path leaks into the child's environment (`process.go`'s never-inherited-Env discipline). |
| T-08-17 | Tampering | inbound frame parsing | high | mitigate | `maxFrameBytes` bounds every line before allocation; unknown `kind`, malformed JSON, and oversized frames are protocol violations that fail closed rather than being ignored. |
| T-08-18 | Elevation of Privilege | method dispatch | high | mitigate | Only methods present in `scriptsdk.RegisteredSDKMethods()` reach the Executor; anything else returns `GOLC_SCRIPT_METHOD_UNKNOWN` without touching the registry. `registryExecutor` re-checks the route as defence in depth. |
| T-08-19 | Information Disclosure | captured stdout/stderr | high | mitigate | Every captured line passes `internal/security.Redact` and a bounded drop-oldest buffer before it can reach a caller, an audit row, or an event — `process.go`'s exact pattern, applied to all output rather than only failure diagnostics. |
| T-08-20 | Denial of Service | unbounded output | medium | mitigate | `boundedBuffer`'s fixed capacity plus `maxFrameBytes` cap memory a runaway script can force the daemon to hold. Hard CPU/memory/deadline enforcement is 08-06's task. |
| T-08-21 | Tampering | materialized script file | medium | mitigate | The script is written into a fresh `os.MkdirTemp` directory per run, removed on every exit path including kill; `cmd.Dir` points there so a relative path in the child resolves nowhere useful — and the child holds no filesystem permission regardless. |
| T-08-09 | Tampering | module resolution | high | mitigate | The SDK is injected as an ambient global shim concatenated ahead of the user source; no import statement is generated or injected, so Deno's resolver is never handed a specifier (08-RESEARCH.md Pitfall 4). 08-07 adds the validation gate that rejects a user-authored import. |
</threat_model>
