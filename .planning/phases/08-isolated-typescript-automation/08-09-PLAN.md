## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a user can launch a script in Debug mode, hit a breakpoint, step through it, inspect where it stopped, and read a crash as a real source-mapped stack trace — with the debug channel existing only in Debug mode.

<objective>
Implement D-01's real interactive debugger, D-02's Debug-mode-only inspector gating, and D-03's source-mapped stack traces, with the Go daemon as the sole CDP client (SCRP-01's debug verb, SCRP-05's source locations).

Purpose: D-01 was the user's one deliberate departure from the lighter-weight recommendation. The debug-mode gate (D-02) exists specifically so that shipping a real debugger does not weaken the default sandbox posture — the gate is the load-bearing part of this plan, not an incidental detail.
Output: `debugbridge.go`, `stacktrace.go`, and `internal/command/scriptdebug.go`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon → inspector socket | A debug-protocol channel into the sandboxed process is a privileged control path. |
| inspector → any other local process | An open loopback inspector port is reachable by anything running as the same user. |
| CDP output → user-visible traces | Attacker-controlled text and real filesystem paths flow outward. |

## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain "Inspector/debug channel exposure enabling arbitrary code execution or state inspection" row and §Common Pitfalls Pitfall 2.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-39 | Elevation of Privilege | inspector channel existence | high | mitigate | The inspector argument is appended at exactly one site, gated purely on the explicit user-selected `LaunchMode`. No env var, build tag, or config key can add it. Proven by `TestNoInspectorOutsideDebugMode` against a real Run-mode process, not by inspection (D-02, structural rather than conventional). |
| T-08-40 | Information Disclosure | inspector port exposure | high | mitigate | Bound to loopback on an ephemeral port; the Go daemon is the sole CDP client and no exported method returns the port, URL, or a raw frame, so the browser/webview attack surface never includes it. |
| T-08-41 | Elevation of Privilege | debugger as a limit bypass | high | mitigate | Pausing at a breakpoint does not suspend the deadline context or the Job Object; a paused run past its deadline is terminated exactly like a running one, asserted by a dedicated test and recorded in a doc comment so the "pausing shouldn't count" change is not made casually. |
| T-08-42 | Information Disclosure | stack-trace paths | medium | mitigate | `parseStackTrace` replaces the temp path with the script's user-facing name and passes every extracted string through `security.Redact`; a test asserts no frame contains the temp directory path. |
| T-08-43 | Tampering | CDP protocol handling | medium | mitigate | A generated, type-safe Go CDP client is used rather than a hand-rolled WebSocket plus raw JSON, avoiding a class of protocol-drift bugs across CDP's hundreds of typed methods and events. |
| T-08-44 | Denial of Service | dropped CDP connection | low | accept | An unexpectedly dropped inspector connection records `GOLC_SCRIPT_DEBUG_DISCONNECTED` and the run continues to its normal termination under the Job Object and deadline. Accepted because the failure mode is a lost debug view, not a lost safety guarantee — the kill path never depends on CDP. |
</threat_model>
