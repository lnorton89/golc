## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a user can validate a script before running it and get real TypeScript diagnostics pointing at real lines in their own source — and a script that tries to reopen the module-resolution surface is rejected outright.

<objective>
Implement SCRP-01's validate verb: the structural zero-import gate (D-14, SCRP-03's supply-chain surface) and a `deno check` type-check against the generated SDK types, with diagnostics mapped back into the author's own source coordinates.

Purpose: validation is the phase's cheapest safety gate. It is where an import statement is caught before Deno's resolver ever sees it, and where a type error is caught before a partially-correct script mutates a live show.
Output: `internal/script/validate.go`, `internal/script/diagnostics.go`, and `internal/command/scriptvalidate.go`.
</objective>

Create `internal/script/validate.go` and implement `func checkForbiddenModuleSyntax(source string) []Diagnostic`. ## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain "Supply-chain injection via script import statements" row and ASVS V5 Input Validation.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-29 | Tampering | module resolution | high | mitigate | The structural gate rejects any import/export/dynamic-import before any subprocess is spawned, so Deno's resolver is never handed a specifier — closing the gap 08-RESEARCH.md Pitfall 4 identifies between resolution and permission checking. Comment/string-literal stripping prevents the gate from being either bypassed or falsely tripped. |
| T-08-30 | Tampering | validation subprocess flags | high | mitigate | `buildDenoCheckArgs` is a dedicated single composition site returning `check --no-prompt --cached-only <path>`; the same `forbiddenDenoArgPrefixes` assertion 08-05 uses is applied to it, and `--cached-only` denies resolution-time network access as a second layer. |
| T-08-31 | Information Disclosure | captured tool output | medium | mitigate | `deno check` stdout/stderr passes through a bounded buffer and `security.Redact` before becoming a diagnostic message, so a path or value the tool echoes cannot leak unredacted into the UI or a log. |
| T-08-32 | Spoofing | diagnostic line numbers | medium | mitigate | The shim offset is computed from the materialized file rather than hardcoded, and an in-shim position is reported under a distinct code instead of a nonsensical negative user line — so a diagnostic can never silently point at the wrong line of the author's code. |
| T-08-33 | Denial of Service | validation of a huge script | medium | mitigate | The 1 MiB source bound is checked first, and the check runs under `exec.CommandContext` with the caller's context so a hung `deno check` is cancellable. |
</threat_model>
