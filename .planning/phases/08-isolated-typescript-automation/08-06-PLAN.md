## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note:** see 08-01-PLAN.md's Phase Goal section.

**This plan's slice:** after this plan, a user's capability profile actually binds — an over-scope call, an over-deadline run, an over-rate burst, or a memory/CPU runaway is killed immediately with a named reason, and the user can stop a script by hand without touching the show.

<objective>
Enforce D-06's scopes, D-08's immediate hard termination, D-09's resolved limits, D-10's per-script Stop, D-11's in-flight-command semantics, and D-13's no-auto-restart rule — at the OS-process boundary where they are structurally, not conventionally, true (SCRP-04, SCRP-06).

Purpose: the phase's promise is that a script cannot own or delay deterministic output. That is only true if a runaway script dies immediately and the kill path cannot be intercepted or delayed by the script.
Output: `capability.go`, the Job Object pair, `internal/command/scriptstop.go`, and the Art-Net non-interference proof.

**Flagged assumption to record in the SUMMARY (SCRP-06, unclassified edge probe — surfaced, not silently dropped):** the spec-less probe classified SCRP-06's edge category as `unclassified`, so no automated edge criterion was derivable. The planner's judgment is that SCRP-06's operative edge is *kill-path uninterceptability*: a script must not be able to delay or survive its own termination via a `finally` block, a `Deno.addSignalListener`, an unhandled-rejection handler, or a long-running microtask. The chosen mitigation is Job-Object close (kernel-enforced, unmaskable) rather than a cooperative shutdown signal, verified by Task 3's adversarial test. If a reviewer disagrees that this is SCRP-06's operative edge, raise it before 08-08 builds the terminal-status event on top of this behaviour.

**Flagged assumption carried from 08-RESEARCH.md Assumption A2:** CONTEXT.md's D-08 names "deadline, rate limit, or resource limit" but not capability-scope violations. This plan treats an out-of-scope SDK call with the same immediate-hard-termination severity, because the alternative (a soft catchable error) reads to a script author as "the SDK is broken" rather than "you crossed a boundary". Recorded here as an explicit planner extension of D-08, not a silent one.
</objective>
