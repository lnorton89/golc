## Phase Goal

**ROADMAP goal (verbatim):** Users can create and debug typed TypeScript automation in a supervised, capability-limited process that cannot own or delay deterministic output.

> **MVP-mode note (planner-surfaced, non-blocking):** MVP mode expects the phase goal in user-story form (**As a** / **I want to** / **so that**). The Phase 8 `**Goal:**` line in ROADMAP.md is not in that form. Per the user-story rule a story is never invented from a non-story goal — run `/gsd mvp-phase 8` if the user-story framing is wanted. The vertical-slice ordering across plans 08-01…08-11 is unaffected.

**This plan's slice:** after this plan, a user can create, list, inspect, edit, delete, and profile a TypeScript script that lives inside their `.golc` show file and travels with it — through the CLI surface every GOLC workspace is built on top of. Nothing executes yet; that is 08-05's slice.

<objective>
Add the `Script` entity and its capability profile to `show.State` (D-17, D-14, D-06, D-07, D-09) and the `script` CLI command graph that creates, lists, shows, edits, deletes, and profiles them (SCRP-01's create/edit verbs, SCRP-04's assignment surface).

Purpose: every later plan in this phase — the Deno host, the SDK, the workspace, the debugger — reads and writes this one entity. Getting its shape, identity, and validation right first means no later plan has to re-litigate where a script lives or which scope enum it uses.
Output: `internal/show/scripts.go`, the `Scripts` field on `show.State`, and `internal/command/script.go`'s self-registered route graph.
</objective>

Declare the scope once with `var _ = MustDeclareScope(ScopeRegistration{Scope: "script", Summary: "..."})` and declare each route with its own package-level `var _ = MustDeclareRoute(CommandRegistration{Route: "script create", ...})` initializer — `script create`, `script list`, `script show`, `script edit`, `script delete`, `script profile set`.

Every handler: parse args with the same flag discipline `internal/command/scene.go` uses, resolve `--show <path>` against `request.Root`, `show.Load`, mutate the `Scripts` slice, `show.Save` (which runs `validate` and bumps `Revision`), and marshal deterministic JSON to `Result.Stdout`. Reuse `internal/strictjson` for output if scene.go does. Exit-code contract is unchanged: 0 success, 1 handler failure with the domain diagnostic on Stderr, 2 malformed/unroutable.

`script edit` takes `--source-file <path>` and reads that file's bytes verbatim into `Script.Source` — no normalization, no transpile, no reformat. It must reject a source file larger than a declared `maxScriptSourceBytes = 1 << 20` (1 MiB) with `GOLC_SCRIPT_SOURCE_TOO_LARGE`, so a pathological file can never be committed into the show blob.

`script profile set` accepts `--scope`, `--preset`, and the advanced overrides `--deadline-seconds`, `--rate-per-second`, `--memory-limit-mb`, `--cpu-cap-percent`. Unset flags leave the existing profile field untouched (this is a per-script *saved default*, D-07 — a partial edit never silently resets the other fields).

`script list`'s JSON is the exact projection the D-16 library view consumes: an array of objects with `id`, `name`, `last_run_status`, `last_run_reason`, and `capability_profile`. It deliberately omits `source` so listing a show with many large scripts stays cheap.

## STRIDE Threat Register

Grounded in 08-RESEARCH.md §Security Domain (ASVS V5 Input Validation, ASVS V4 Access Control rows).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `show.State.Scripts` persistence | medium | mitigate | Scripts live in the existing single validated blob; `validate()` runs `ValidateScript` + `ValidateScriptUniqueNames` on every Save, so no unvalidated script can be committed (ASVS V5). |
| T-08-02 | Elevation of Privilege | `CapabilityProfile.Scope` | high | mitigate | `Scope` is typed `show.APIKeyScope` and validated against the existing closed set; an unrecognized value fails with `GOLC_SCRIPT_SCOPE_INVALID` rather than defaulting to a broader scope. `NewScript` defaults to the least-privileged `playback` scope (ASVS V4, D-06). |
| T-08-03 | Denial of Service | `script edit --source-file` | medium | mitigate | `maxScriptSourceBytes` (1 MiB) rejects an oversized source before it enters the blob, so a single script cannot bloat every autosave/recovery point. |
| T-08-04 | Elevation of Privilege | resolved limits | high | mitigate | `ResolveResourceLimits` maps a zero/negative/absent custom value onto the package-level safe default (`internal/api/ratelimit.go`'s discipline) — an unset limit is never "unlimited". |
| T-08-05 | Elevation of Privilege | show-file import | high | mitigate | Nothing in this plan executes a script. Prohibition: loading, importing, or migrating a `.golc` file must never auto-run a contained script. Verified structurally — no execution seam exists until 08-05, and 08-05 gates every run behind an explicit user route invocation. |
</threat_model>
