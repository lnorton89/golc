## Phase Goal

**FLAGGED — MVP user-story format discrepancy** (see 09-01-PLAN.md). ROADMAP goal, verbatim:

> A new operator can go from a fresh checkout to a patched fixture and a scene on screen using only
> the UI, with Guided First Show onboarding as the on-ramp — no CLI required for the happy path.

This plan's slice: a first-time operator with an empty show is met by the guide and walked through
getting a fixture and a patch in place.

<objective>
Build the Guided First Show overlay — its entry points, its locked stage rail and evidence aside, and
the first two stages (Fixtures, Patch) — driven entirely by live reads of real domain state.

Purpose: FDUI-03's first half. There is zero onboarding code in `frontend/src` today, but the design
is fully locked by `.planning/sketches/references/onboarding-readiness-impact.md` (Sketch 004
Variant B), which is explicitly not up for re-litigation. D-08 and D-10 answered only WHEN and WHERE
the flow is invoked; this plan implements exactly that plus the overlay's structure.

Output: `GuidedFirstShow/` component tree, the guide context wired into `AppShell`, and Overview's
`Start Guide` action plus empty-show auto-launch.
</objective>
