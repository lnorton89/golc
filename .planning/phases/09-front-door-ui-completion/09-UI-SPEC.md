# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately bypassed at Phase 6, reaffirmed at Phase 8; same rationale applies unchanged (`.planning/research/STACK.md`'s instruction to avoid a theme framework that dictates console density) |
| Preset | not applicable |
| Component library | none (no Radix/base-ui) — reuses `frontend/src/components/primitives/*` (Button, Panel, PanelHeader, Toolbar, ScrollRegion, EmptyState, Chip, Field, ListRow) established through Phases 6–8 |
| Icon library | **`lucide-react` (`^1.27.0`, `frontend/package.json`)** — grounded correction: `08-UI-SPEC.md` declared icon library "none," but the installed dependency and every actually-delivered file (Button/Chip/EmptyState/ListRow/Toolbar/PanelHeader primitives; `SaveRecoveryWorkspace.tsx`'s `Save/Copy/History/Check/Trash2`; `ScriptsWorkspace.tsx`'s `FileCode2/Plus/Play/Bug/Square`; `OverviewWorkspace.tsx`'s `LayoutDashboard/Activity/Package/Boxes`) contradict that. Phase 9's three new surfaces use `lucide-react` via the exact same `icon={IconComponent}` prop convention every existing primitive already uses — never a new icon system. |
| Font | Archivo (UI text/labels/headings) + JetBrains Mono (technical/code) — unchanged |

**Navigation and entry points (D-08/D-09/D-10, locked by 09-CONTEXT.md):**
- Fixture Library replaces the `ComingSoon` stub at the existing `build-fixture-library` nav destination (`frontend/src/workspaces/build/FixtureLibraryWorkspace.tsx`) — no navigation change needed, only the workspace body.
- Show open/new/switch gets **one new destination in the Show nav group** (`frontend/src/shell/navigation.ts`'s `NAV_GROUPS[0]`), alongside the existing Overview, Save & Recovery, and Settings entries. Nav label: **"Shows"** (plural noun, matching the group's existing noun-only naming convention — not a verb phrase like "Open Show").
- Guided First Show is **not** a nav destination. It is an overlay/flow that replaces the canvas content: auto-launched by `OverviewWorkspace` (or its successor) when the show has no fixtures/pools/scenes (D-08), or manually entered via a **"Start Guide"** button on Overview (D-10). Exiting returns to whichever workspace was active before entry.
- No new frontend package is required for D-04's native file picker — it is a Go-side Wails runtime call (`runtime.OpenFileDialog`), not a frontend dependency, and carries no registry-safety concern.

**Primary visual anchor per surface:**
- **Fixture Library:** the combined local/OFL list is the focal point; the inline inspect panel is secondary and stays visually quiet (collapsed/empty) until a row is selected, at which point it takes the eye via the accent-toned "Add to Library" CTA.
- **Shows workspace:** the current-show indicator plus its "Open Show…" / "New Show…" action pair is the focal point — the operator's eye should land on "what show am I in, and how do I change it" before anything else on the surface.
- **Guided First Show:** the active stage's primary action button in the stage content pane is the focal point (reinforced by the stage rail's `aria-current="step"` highlight as a secondary anchor pointing at it); the readiness/evidence aside is tertiary, consulted after the primary action, not competing with it.

## Spacing Scale

Declared values (multiples of 4), identical to the project-wide scale Phase 6 established and Phase 8 reused unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-inline gaps in list rows/chips; evidence-list bullet spacing in the Guided First Show readiness panel |
| sm | 8px | Compact element spacing; Fixture Library row internal padding; guide-step list item spacing |
| md | 16px | Default element spacing; panel internal padding; Fixture Library search bar padding |
| lg | 24px | Section padding — Guided First Show stage-content padding; Fixture inline inspect panel padding |
| xl | 32px | Layout gaps between major panels — Fixture Library list ↔ inspector; Guided First Show stage-rail ↔ content ↔ evidence aside |
| 2xl | 48px | Major section breaks — between Overview's new "Start Guide" CTA block and the rest of Overview |
| 3xl | 64px | Page-level spacing; unchanged, unrelated to this phase (safety-cluster touch target) |

Exceptions:
- **Guided First Show's `.guided-flow` grid gap is locked at 7px** (D-11, `09-CONTEXT.md`), verbatim from `onboarding-readiness-impact.md`'s own committed CSS pattern (`grid-template-columns: 210px minmax(0, 1fr); gap: 7px;`). Not a multiple of 4 — D-11 formally records this as a locked-decision-weight exception (same weight as D-01..D-10), not merely a UI-SPEC prose note: the value is a pre-existing, already-approved constraint inherited verbatim from an explicitly "do not re-open" sketch reference, so the executor reproduces it verbatim rather than rounding to 8px.
- **Guided First Show's stage rail is a fixed 210px column width** (same locked CSS, same D-11) — a layout dimension, not a spacing-scale token.
- **Native file/directory picker dialogs** (D-04's custom-YAML path field, D-05/D-06's show-path picker) render through OS/Wails runtime chrome, outside this app's spacing scale.

- Fixture identity/provenance values (stable key, content hash, schema/revision, OFL manufacturer/key) render in the **Technical readout** row — the same size/family as `OverviewWorkspace`'s existing `Schema {v} · Revision {r}` treatment and every `GOLC_*` diagnostic code elsewhere in the app.

- Stage headings and empty-state headings use **Heading**; stage explanatory copy uses **Body**.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#E4E0D8` light / `#131419` dark (`--page`) | Application canvas background, unchanged |
| Secondary (30%) | `#F4F1EB` light / `#1E2027` dark (`--panel`) | Fixture Library list rows and inline inspect panel; Shows workspace panel surfaces; Guided First Show stage-rail and content panel surfaces |
| Accent (10%) | `#1B44D9` Signal Blue (`--accent`) | See explicit reserved-for list below |
| Destructive | `#E23A2E` (`--status-revoked`) | None newly introduced this phase — see rationale below |

**Accent reserved for, explicitly:**
- Fixture Library: the primary "Add to Library" confirm button (filled `primary` Button variant), the selected fixture row in the combined local/OFL list, the search input's focus ring
- Shows workspace: the primary "Open Show…" / "New Show…" action buttons, the current-show indicator
- Guided First Show: the current stage in the rail (`aria-current="step"` — 3px left border + `--color-primary-soft` background, per the locked CSS pattern verbatim), each stage's one dominant primary action button, focus rings

**Destructive rationale:** No destructive-confirmation action is newly introduced this phase. "Add to Library," "Open Show…," "New Show…," "Switch," "Continue," and "Exit Guide" are all non-destructive — Guided First Show's Exit Guide always retains progress and evidence per the locked design (`onboarding-readiness-impact.md`: "Exiting retains completed evidence and current stage"), so it renders as the neutral `secondary` Button variant, exactly like Phase 8's Debug-dialog "Cancel"/"Back." If a later gap-closure round adds a "discard unsaved changes before switching" confirmation, it should reuse the existing `destructive` `Button` pattern already established by `SaveRecoveryWorkspace.tsx`'s "Discard All" — not a new color.

### Status Vocabulary (semantic, not part of the 60/30/10 split)

Reused directly from the existing six-color system (`index.css`); Phase 9 maps fixture-validation and readiness states onto it rather than inventing new state colors:

| Status | Value | Phase 9 usage |
|--------|-------|----------------|
| live | `#1B44D9` | Not used by this phase (playback-specific) |
| frame-lock | `#5AC26A` | Fixture validation "Valid" chip in the inline inspect panel (same tone `OverviewWorkspace`'s "Healthy" chip already uses); Guided First Show readiness "Evidence" (met) status |
| armed | `#C8A24B` | Fixture import "lossy/unsupported attribute(s)" warning chip (FIXT-06); Guided First Show readiness "Warning" status (acknowledgment needed, not blocking) |
| revoked | `#E23A2E` | Fixture validation "Invalid" chip; Guided First Show readiness "Blocker" status (blocks only the transition to Perform, per the locked interaction contract) |
| offline | `#8A887F` | OFL catalog search unreachable (network/SSRF-guarded fetch failure); daemon/show-service unreachable during Open/New/Switch |
| blackout | `#17181C` | Not used by this phase (global safety-specific) |
