## Phase Goal

**FLAGGED — MVP user-story format discrepancy** (see 09-01-PLAN.md). ROADMAP goal, verbatim:

> A new operator can go from a fresh checkout to a patched fixture and a scene on screen using only
> the UI, with Guided First Show onboarding as the on-ramp — no CLI required for the happy path.

This plan's slice: imported fixtures become visible in the library, and the operator can search the
Open Fixture Library catalog from inside the app.

<objective>
Make the fixture-import artifact a first-class library citizen, and add Open Fixture Library catalog
search to the Fixture Library workspace (D-01's catalog half, D-03).

Purpose: FDUI-01. Two gaps close here. First, `fixture import --out` writes a JSON
`{definition, provenance}` envelope that neither the library listing nor the Art-Net fixture resolver
can read today, so an imported fixture is invisible to the very surfaces that should use it. Second,
there is no way to discover a fixture in the OFL catalog from inside the app at all.

Output: `internal/fixture/envelope.go`, `.json` support in `ListDirectory`,
`internal/fixture/ofl/manufacturers.go`, `FixtureLibraryService.SearchOFL`, and the workspace's
source toggle with catalog results.

**Scope decision requiring the developer's attention** (surfaced, not silently taken): this version
searches the OFL catalog by **manufacturer name only**. `09-RESEARCH.md` Open Question 1 established
that no full fixture-name index is committed to the OFL repository and none is reachable from the
single host the SSRF guard allows; fixture-model search would require adding `api.github.com` as a
second allowed host with a 60-request/hour unauthenticated rate limit — a discrete security decision
RESEARCH explicitly recommends deferring. The consequence is carried honestly into the UI (the
operator supplies the fixture key) and recorded as an OPT-OUT with its reason in
`.planning/phases/09-front-door-ui-completion/COVERAGE.md`.
</objective>
