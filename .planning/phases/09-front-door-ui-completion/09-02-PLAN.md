## Phase Goal

**FLAGGED — MVP user-story format discrepancy** (see 09-01-PLAN.md; `ROADMAP.md`'s Phase 9 `**Goal:**`
line is not in `As a / I want to / so that` form, so no user story is invented here). ROADMAP goal,
verbatim:

> A new operator can go from a fresh checkout to a patched fixture and a scene on screen using only
> the UI, with Guided First Show onboarding as the on-ramp — no CLI required for the happy path.

This plan's slice: the operator can open, create, and switch between shows entirely on screen.

<objective>
Add on-screen show open / new / switch controls, implemented as a supervised self-relaunch of
`golc-desktop.exe` with a new `GOLC_DESKTOP_SHOW` (D-05, D-06, D-07).

Purpose: FDUI-02. Today `cmd/golc-desktop/main.go` binds all nine constructed Wails services to one
`cfg.ShowPath` read once at process startup, and the only way to change it is to set an environment
variable and relaunch the executable by hand. This plan surfaces that as two buttons and makes the
application perform the relaunch itself.

Output: `App.PickShowPath`/`PickNewShowPath`/`RelaunchWithShow` on the already-bound `App` struct, a
new `Shows` destination in the Show nav group, and `ShowsWorkspace.tsx`.

Planner decision (resolves `09-RESEARCH.md` Open Question 2, which CONTEXT.md and the UI-SPEC both
leave open): the switch **auto-saves the working show before relaunching** rather than prompting.
This is the lower-risk default — it never silently loses work and needs no new UI copy beyond what
the Copywriting Contract already locks. A save that fails aborts the switch.

Planner decision (resolves `09-RESEARCH.md` Open Question 3): `PickShowPath`/`PickNewShowPath`/
`RelaunchWithShow` live on `App`, which already owns process-lifecycle concerns (daemon spawn/kill,
hotkeys, event pusher) and is already in the `Bind` list — not on `ShowService`, which owns
ShowState CRUD, a different concern.
</objective>

Add `func (a *App) RelaunchWithShow(newShowPath string) Result`, returning this package's existing `Result` shape, executing strictly in this order:
1. Trim the argument. If empty, return `ExitCode: 1` with `GOLC_WAILS_RELAUNCH_PATH_EMPTY` on stderr. No save, no spawn, no quit. Do not special-case a path equal to the current `cfg.ShowPath` and do not special-case a path whose file does not yet exist — both take the identical path (D-06).
2. Compare-and-set the `relaunching` guard under the mutex. If it was already set, return `ExitCode: 1` with `GOLC_WAILS_RELAUNCH_IN_PROGRESS`. Every failure path below clears the guard before returning; the success path deliberately leaves it set, since the process is exiting.
3. 4. Resolve `os.Executable()`. On failure return `ExitCode: 1` with `GOLC_WAILS_RELAUNCH_SPAWN_FAILED`; nothing has been touched yet.
5. Call `stopSupervisedDaemon()` so the named pipe is free before the replacement starts — otherwise the replacement's own `ensureDaemon` dials successfully and silently attaches to a daemon still bound to the OLD show path.
6. Call `a.relaunchSpawn(exePath, append(os.Environ(), DesktopShowPathEnvName+"="+trimmedPath))`. On failure, call `a.ensureDaemon(a.ctx)` to restore daemon supervision for the still-running process, clear the guard, and return `ExitCode: 1` with `GOLC_WAILS_RELAUNCH_SPAWN_FAILED`. Do not call quit.
7. Only on spawn success, call `a.quit(a.ctx)` and return `ExitCode: 0` with `GOLC_WAILS_RELAUNCH_STARTED` on stdout.

The default `relaunchSpawn` implementation builds `exec.Command(exePath)` — deliberately NOT `exec.CommandContext`, because the stored ctx is cancelled by this process's own exit and would kill the replacement — sets `cmd.Env` to the supplied slice, and calls `cmd.Start()`. It never invokes a shell, so the show path is an environment assignment and never a shell-interpreted string. The default `quit` implementation is the Wails runtime quit.

Document in `App`'s doc comment the one accepted limitation: when the daemon was started outside this process (this `App` never spawned it), `stopSupervisedDaemon` is a no-op and the replacement may attach to an externally managed daemon still bound to the previous show — an operator-managed daemon is outside this process's supervision.
