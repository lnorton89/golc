## Phase Goal

**FLAGGED — MVP user-story format discrepancy** (see 09-01-PLAN.md). ROADMAP goal, verbatim:

> A new operator can go from a fresh checkout to a patched fixture and a scene on screen using only
> the UI, with Guided First Show onboarding as the on-ramp — no CLI required for the happy path.

This plan's slice: the operator can add their own hand-written fixture definition without leaving the
app.

<objective>
Add the hand-authored YAML fixture path to the Fixture Library: point at a local file through a
native picker or a typed path, validate it inline, then add it (D-04, FIXT-04).

Purpose: FDUI-01's last path. Plans 09-05 and 09-06 covered the Open Fixture Library catalog; a show
author who writes their own definition still has no on-screen route into the library. D-04 fixes that
with a file picker and inline validation — explicitly not an in-app YAML editor.

Output: `App.PickFixtureFile`, `FixtureLibraryService.PreviewFile`, and the workspace's custom-fixture
affordance reusing the existing candidate panel and confirm action.
</objective>

In `internal/wails/svc_fixturelibrary.go`, first replace the destination derivation in `CommitPreview` with an in-memory preview registry: `PreviewOFL` and the new `PreviewFile` each record the token together with the destination file name they computed, and `CommitPreview` reads the destination from that registry rather than re-deriving it from the artifact. This is what lets one commit path serve both a JSON import artifact and a hand-authored YAML file without the Wails layer ever decoding a fixture document itself. Every plan 09-06 preview and commit test must pass unchanged.

Add `PreviewFile(path string) (FixturePreviewView, error)`:
1. Run `s.Inspect(path)` — the existing method that forwards to the registered `fixture inspect` route. This is the sole validation authority; the Wails layer performs no decode, no validate, and no pin of its own.
2. When the inspect result is invalid, return the view carrying those errors, stage nothing, and return a nil error — an unreadable path and an invalid definition both take this same path so there is exactly one error surface, as the UI-SPEC requires.
3. When valid, derive the destination file name from the inspect result's stable key by lowercasing it and replacing every character that is not a letter, digit, or hyphen with a hyphen, collapsing runs, and appending the source file's own extension so the operator's YAML stays YAML. Copy the operator's file byte-for-byte into the preview directory, register the token with that destination, and return the view including whether the destination already exists. A copy failure returns `GOLC_WAILS_FIXTURE_PREVIEW_STAGE_FAILED`.

`CommitPreview` and `DiscardPreview` need no behavioural change beyond the registry lookup — the existing containment check, the existing already-exists refusal, and the existing explicit-overwrite path all apply to a custom fixture identically.

In `wailsBridge.ts`, extend `AppBinding` with `PickFixtureFile(): Promise<string>` and `FixtureLibraryServiceBinding` with `PreviewFile(path: string): Promise<FixturePreviewView>`, and export `pickFixtureFile()` and `previewFixtureFile(path)` following the same never-throw contract as the existing exports — the picker returns an empty string when the binding is absent, matching the cancellation outcome.

## Trust Boundaries

|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-07-01 | Tampering | A definition accepted on screen that the canonical pipeline would reject | high | mitigate | `PreviewFile` obtains its verdict exclusively from the registered `fixture inspect` route; a source assertion pins that no decode, validate, or normalize call exists in the Wails service, so the GUI can never be more permissive than the CLI |
| T-09-07-02 | Tampering | Staging or committing outside the intended directories via a crafted token | high | mitigate | The preview containment check and the already-exists refusal introduced in plan 09-06 apply unchanged; the registry only maps a token this service issued to a destination this service computed |
| T-09-07-03 | Information Disclosure | An arbitrary operator-supplied path read by the backend | low | accept | Single-operator local desktop trust model, and the operator is choosing their own file through their own OS picker.
