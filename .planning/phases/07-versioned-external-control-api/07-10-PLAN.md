## Phase Goal

**As an** integrator, **I want to** inspect and control every public GOLC capability through a secure, versioned, revision-aware HTTP API, **so that** external programs behave exactly like the desktop application.

<objective>
Close verification gap 1 (API-01 breadth, Success Criterion #1) by the route the developer already chose: formally re-scope API-01's "every capability" claim to the capabilities Phase 7 actually delivered, and record the remaining domains against a named, greppable deferral owner instead of leaving them as unattributed "future work".

Purpose: 07-VERIFICATION.md scored Success Criterion #1 FAILED because only 6 of ~86 real command routes are reachable over /v1 while 61 sit in exclusion categories the code itself labels as still-owed work. The developer's decision for this round is to narrow the claim, not to wire more routes.
Output: an honest ROADMAP Success Criterion #1, a narrowed API-01, a new EXTN-05 (v1.x) requirement owning the deferred breadth, and a mechanical test that the deferral pointer cannot be silently deleted.

NOT in this plan: any new REST operation, Huma input struct, or RegisterOperation call. This plan wires zero routes by design.
</objective>
