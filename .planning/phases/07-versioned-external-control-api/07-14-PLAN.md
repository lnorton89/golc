<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published compatibility policy → integrator detection logic | Clients build automated deprecation detection against documented response headers; a documented-but-unemitted signal is silently trusted |
| admin-scoped caller → minted credential lifetime and scope set | The mint request chooses how long a credential lives and what it can reach; both are safety controls a caller can currently set without bound |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-28 | Repudiation | `buildRouter` never installing `DeprecationMiddleware` | medium | mitigate | Install it unconditionally (a no-op for non-deprecated operations) and pin the wiring with a source-discipline test plus a live-request header test, so a documented client-detection signal cannot silently fail to appear. |
| T-07-29 | Elevation of Privilege (persistence) | unbounded `expires_in` on POST /v1/keys | medium | mitigate | Documented `maxAPIKeyLifetime` ceiling enforced at the HTTP boundary with a typed 400 naming the bound; the scoped, revocable key stays genuinely time-limited rather than effectively permanent. Admin scope is still required to mint at all, which is why this is medium rather than high. |
| T-07-30 | Tampering / Elevation of Privilege | comma-joined `scopes` list splitting into unintended scope values | medium | mitigate | `validateListValues` (07-13) refuses any scope element containing the reserved delimiter before `strings.Join`, closing the one delimiter-joined field where a split value could widen a credential rather than merely mis-shape show content. |
| T-07-30b | Denial of Service | a rejected mint attempt costs the server a parse and a scope check | low | accept | Every /v1 request already passes `AuthMiddleware` and per-key `RateLimitMiddleware`, and minting additionally requires the admin scope, so the reachable request rate is already bounded. |
| T-07-31 | Information Disclosure | the new diagnostics echo the requested duration and the offending scope value back to the caller | low | accept | Both are values the caller itself supplied in the same request; neither reveals server state, and neither is a credential (the raw token is generated downstream and never reaches these branches). |

No package-manager installs (npm/pip/cargo) occur in this plan, so no supply-chain legitimacy checkpoint (T-{phase}-SC) applies.

Canon-referral breadcrumb: general credential-lifetime and session-management canon (OWASP ASVS V3) is owned by `/gsd-secure-phase`; only the bespoke product decision — that a GOLC API key must not outlive the compatibility window the project itself publishes — is minted as a prohibition here.
</threat_model>
