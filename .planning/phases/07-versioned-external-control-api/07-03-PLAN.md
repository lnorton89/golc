## Phase Goal

**As an** integrator, **I want to** inspect and control every public GOLC capability through a secure, versioned, revision-aware HTTP API, **so that** external programs behave exactly like the desktop application.

<objective>
Replace 07-02's hardcoded loopback bind with a real `api` configuration concern (D-06), and enforce loopback-by-default at bind time (Pitfall 4). After this slice, an operator can flip `api.remote_enabled` in config to expose the API beyond loopback (with an explicit interface), and the default — and any misconfiguration — resolves to a safe loopback-only bind.

Purpose: API-05's "loopback by default, explicit enablement for remote access" must be a mechanically enforced default, not documentation. Declaring one `api` concern here also provides the port and rate-limit keys 07-04 will consume.
Output: `config/api.toml` + a registered `api` concern + config-driven, loopback-default bind derivation.
</objective>
