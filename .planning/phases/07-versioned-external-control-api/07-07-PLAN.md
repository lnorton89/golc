## Phase Goal

**As an** integrator, **I want to** inspect and control every public GOLC capability through a secure, versioned, revision-aware HTTP API, **so that** external programs behave exactly like the desktop application.

<objective>
Record every API mutation (success, failure, rejection, and dry-run) as one auditable, redacted row in a new `audit_log` table inside the .golc show store (D-16), written through internal/show's single-writer machinery. After this slice, every state change made through the API leaves an accountable trail that travels with the show file.

Purpose: API-06 (actor/source/correlation/outcome/redacted details). The audit writer attaches to 07-05's post-mutation observer seam, so it captures single mutations (07-05) and atomic batches (07-06) without touching either.
Output: audit_log table + a redacting post-mutation audit writer.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-11 | Information Disclosure | secret leaked into audit_log.redacted_details | high | mitigate | strip-before-write redaction of Authorization + key/token/secret/password-shaped fields; raw key never reaches the audit path (only the key id is the actor) |
| T-07-11b | Tampering | uncoordinated second SQLite connection for audit writes | medium | mitigate | WriteAuditRecord reuses internal/show openStore (SetMaxOpenConns(1), busy_timeout); no direct sql.Open (grep-asserted) |
| T-07-11c | Repudiation | a mutation leaving no audit trail | medium | mitigate | audit writer attaches to the single post-mutation observer seam that fires for every attempted mutation (success/failure/rejected/dry_run/batch); one row per event asserted by test |
</threat_model>
