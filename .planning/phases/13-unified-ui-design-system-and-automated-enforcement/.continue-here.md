# BLOCKING CONSTRAINTS — Read Before Anything Else

> These were discovered by actual failures. Acknowledge them before resuming.

- [ ] CONSTRAINT: Wails WebView2 CDP — `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` is discarded by Wails v2/go-webview2; use the committed proof-only bridge (`82541bc4`), never retry the old environment-only harness.
- [ ] CONSTRAINT: migration parity — fixture/scene/desk/etc. legacy violations must be converted to tokens/public primitives; DS001 spacing exceptions and broad exception proposals are prohibited.
- [ ] CONSTRAINT: the exception mechanism can only cleanly resolve a match to exactly one diagnostic (`exceptionMatches` in `scripts/design-system/check.mjs` treats 0 or 2+ matches as an error). Two or more diagnostics of the same rule+path with byte-identical values (e.g. duplicate chevron buttons, `.faderInput::-webkit-slider-thumb`/`::-moz-range-thumb` sharing the same `border-radius: 2px`) can never be exempted narrowly — either eliminate the pattern (extract a primitive, as `NumberStepper` now does) or make one of the two values genuinely, minimally different (13-13 superseded a shared thumb radius to a real token; loosened a duplicate `line-height: 1` to `1.1` where no exact-match constraint required identity).
- [ ] CONSTRAINT: `exception.match` can never contain `*`, `?`, or a newline (mechanically rejected as "invalid exception record") — a `clamp()`/`calc()` declaration's own full value (which contains `*` for multiplication) or a multi-line-formatted value can never be its own exact match string; use a shorter, character-safe fragment of the value instead (13-13 used unique suffix fragments like `"0.28), 11px)"`) and collapse multi-line declarations onto one line if their formatting itself contains the forbidden characters positioned across line breaks.
- [ ] CONSTRAINT: a DS001 exception's `match` can never contain the words `padding`, `margin`, `gap`, or `space` (mechanically rejected as "spacing exception", case-insensitive) — this is enforced in code, not just as project policy; any raw spacing literal must go through a real token/architecture fix, never an exception, no matter how narrow or well-documented.
- [ ] CONSTRAINT: a CSS comment containing the literal substring `*/` in its own prose closes early, turning the rest of the comment (and often the following real CSS) into a malformed fragment — `checkCSS`'s bare `postcss.parse()` may tolerate this silently while Vite's real `vite:css`/`postcss-modules-local-by-default` pipeline does not. `tsc`/`vitest` will not catch this either; only a real browser load (or `vite build`) will. Watch for phrases like "--ds-foo-*/--ds-bar-*" or "clamp()/calc()" immediately followed by more prose ending in a stray `*/`-shaped sequence.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---|---|---|---|
| Environment-only WebView2 debugging | It never reaches `msedgewebview2.exe` under Wails v2. | blocking | Preserve and run the committed proof-only local-module/overlay bridge from `82541bc4`. |
| Broad visual-policy exceptions | Fixture and scene migration initially exposed hundreds of legacy violations. | blocking | Convert directory-owned code in bounded passes; add focused tests and require scoped DS checks to pass. |
| Faking packaged evidence | Browser success is insufficient for the shipped desktop contract. | blocking | Keep `dialog-feasibility.json` fail-closed and rerun the packaged proof after seam changes. |
| CSS shorthand mixing a raw literal with a `--ds-*` token | `border: 1px solid var(--ds-border-default)`, `outline: var(--ds-focus-ring) solid var(--ds-focus-color)`, and multi-value `padding`/`transition` all fail DS001's strict single-`var()`-value check even though every operand is a valid token. | recurring | Split into longhand sub-properties (`border-width`/`border-style`/`border-color`, `outline-width`/`outline-style`/`outline-color`, `padding-block`/`padding-inline`) so each individual declaration is exactly one `var(--ds-*)`. Note: `padding-block`/`padding-inline` are still checked by DS001's regex (unlike `row-gap`/`column-gap`, which the regex genuinely omits) — this only helps when the resulting value is itself a bare token, not a way to dodge the check. |
| A dynamic per-instance custom property needing a conditional operator override plus a role-specific default | `color: var(--ds-card-font-color, var(--ds-text-primary))` fails DS001 (not bare) and DS003 (fallback); 3+ identically-shaped call sites collapse to one indistinguishable DS003 diagnostic value. | recurring | Resolve the override-vs-default choice entirely in JS (always set the custom property, per role if roles need different defaults) so the CSS side is a bare `var(--ds-*)` reference with no fallback (13-13: `--ds-card-font-color-primary`/`-secondary`, set unconditionally by `Desk.tsx`). |
