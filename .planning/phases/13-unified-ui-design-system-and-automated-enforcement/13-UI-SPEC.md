# Phase 13 — UI Design Contract

> Visual and interaction contract for the unified GOLC design system, full current-UI migration, and automated enforcement. Generated by gsd-ui-researcher for validation by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | GOLC design system; no shadcn or theme framework |
| Preset | not applicable |
| Component library | Typed React primitives and patterns in `frontend/src/components/primitives/`, built on native HTML semantics; Monaco and Tiptap remain specialized editor integrations |
| Styling approach | Semantic CSS custom properties in an approved token/theme layer plus colocated CSS Modules for feature layout only |
| Icon library | `lucide-react`, line icons with a 24px design grid, 1.75px visual stroke, square caps, and restrained 2px corner radius |
| Font | Archivo for UI prose; JetBrains Mono for technical values, identifiers, channel data, cue numbers, and diagnostics |
| Default visual direction | Existing Paper/Ink console language: dense, flat, border-separated, low-distraction, dark by default, with bounded internal scrolling |

**Source:** D-01 through D-06 in `13-CONTEXT.md`, the Phase 6 and Phase 9 UI contracts, the brand guidelines/tokens, and the validated sketch findings.

**No shadcn rationale:** the application is already a React/Wails product with a purpose-built Paper/Ink token seed and typed primitives. Phase 13 is explicitly a no-rebrand consolidation using the existing stack. Adding Tailwind/shadcn would introduce a second visual and composition layer without solving a missing capability.

### Canonical ownership

The completed design system has exactly four public layers:

1. **Theme definitions** own raw palette values and implement the complete semantic token contract for every supported theme and mode.
2. **Foundation tokens** own typography, spacing, radius, sizing, focus, motion, and stacking values that do not vary by feature.
3. **Typed primitives** own reusable appearance, native semantics, and interaction states.
4. **Typed patterns** compose primitives into repeated product structures such as workspaces, inspectors, impact reviews, and safety controls.

Feature code consumes those layers. Feature code must not define a parallel token namespace, restyle a native control into a duplicate primitive, or branch on `data-theme`, `data-theme-name`, a theme string, or a theme-specific palette value.

### Theme contract

- Preserve all currently selectable theme names and the light, dark, and system mode choices. This phase may reorganize their definitions but may not silently remove a user choice.
- Every theme face exports the same semantic tokens. A missing token is a validation failure; fallback values in feature CSS are forbidden.
- The default theme retains canonical Paper/Ink values. Alternate themes may change palette values, but semantic meaning, component treatment, contrast floor, status vocabulary, and interaction hierarchy stay identical.
- Status colors remain fixed semantic meanings across themes: live, frame-lock, armed, revoked, blackout, and offline. Each use includes text or an icon in addition to color.
- Theme selection remains a cosmetic local preference. It never becomes show state and never changes Go command behavior.

## Semantic Token Contract

Public token names may be generated from a typed manifest, but the exported roles below are mandatory and exhaustive. Existing names such as `--page`, `--panel`, `--ink`, `--accent-*`, and ad hoc feature aliases may remain only inside the approved theme/token implementation during migration; feature consumers use the canonical semantic roles.

| Group | Required roles | Contract |
|-------|----------------|----------|
| Surfaces | canvas, panel, panel-subdued, overlay, control, selected, scrim | Describe elevation/placement, never a palette name |
| Text | primary, secondary, muted, inverse, link | Body copy never uses a raw color or status color |
| Borders | default, strong, selected, destructive | One-pixel structural separation by default; focus is not simulated with border changes |
| Actions | primary, primary-hover, primary-active, on-primary, destructive, on-destructive | Primary action stays visually dominant; destructive is reserved for destructive or safety-stop meaning |
| Status | live, frame-lock, armed, revoked, blackout, offline, and matching readable foreground roles | Meanings are fixed by the brand vocabulary |
| Typography | UI and mono families; compact, body, heading, display sizes; regular and semibold weights; body and heading line heights | Components consume roles, not literal font declarations |
| Spacing | 4, 8, 16, 24, 32, 48, 64px roles | Layout spacing is tokenized on the 4px grid; exceptions cannot bypass the grid |
| Radii | small 4px, medium 8px, large 12px, pill 999px | Flat Paper/Ink treatment; radius communicates component family, not feature identity |
| Sizing | icon 12/16/20/24px; compact/default/minimum-target/safety controls; shell chrome and bounded panel sizes | Repeated geometry is named once; domain geometry is either feature-owned or registered |
| Focus | 2px focus ring, 2px offset, primary-focus color, high-contrast fallback | Every interactive primitive uses `:focus-visible` |
| Motion | snap 0ms, tap 120ms ease-out, settle 200ms ease | Motion communicates state only and yields to reduced-motion preference |
| Stacking | base, sticky chrome, popover, modal, emergency overlay | No feature-local arbitrary `z-index` values |

Token definitions and generated TypeScript/CSS exports must be derived from one reviewed manifest or checked for exact bidirectional equivalence. Documentation, CSS declarations, typed names, and public exports cannot drift.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| 1 | 4px | Icon gaps, compact internal spacing |
| 2 | 8px | Dense rows, button groups, control padding, and compact operational grouping |
| 4 | 16px | Default panel inset, compact panel rhythm, and workspace gap |
| 6 | 24px | Spacious panel inset and dialog padding |
| 8 | 32px | Major layout separation |
| 12 | 48px | Major section or chrome separation |
| 16 | 64px | Page-level break and safety-control minimum height |

Classifications and constraints:

- Guided First Show uses an `8px` grid gap. Phase 13 D-03 explicitly supersedes Phase 9 D-11's inherited `7px` gap; no spacing exception remains.
- The Guided First Show `210px` stage rail is a sizing value, not spacing, and does not require a spacing exception.
- Spacing-grid exceptions are prohibited by Phase 13 D-07; the exception manifest cannot authorize a value outside the declared scale.
- One-pixel borders, two-pixel focus rings, three-pixel active/semantic rails, and icon strokes are visual primitives, not spacing values.
- Shell tracks, resizable rail/inspector bounds, fader tracks, scene timeline geometry, meter geometry, image previews, Monaco/Tiptap internals, and compact visualization coordinates are sizing or domain-visualization values. Repeated values become sizing tokens; genuinely singular values require a narrowly scoped exception.
- Interactive targets are at least 44×44px where controls are icon-only or likely to be operated under pressure. Dense text controls may render 28px or 32px high only when their full row/label supplies a clear pointer target and complete keyboard access.
- Blackout, Revoke Automation, and Stop/Release-All retain a 64px minimum target in any layout that renders them as standalone safety controls. Compact shell placement must still provide at least a 44px target and may not reduce their label visibility or priority.

## Typography

Exactly four type sizes and two weights are public:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Compact label / metadata | 11px | Regular 400 or Semibold 600 | 1.35 |
| Body / control / technical readout | 14px | Regular 400 or Semibold 600 | 1.5 |
| Heading | 20px | Semibold 600 | 1.2 |
| Display / critical live value | 28px | Semibold 600 | 1.2 |

Declared weights: **Regular 400** and **Semibold 600**, no others.

- Archivo is used for prose, navigation, headings, fields, and action labels.
- JetBrains Mono is used for BPM, bar/beat, DMX/channel values, MIDI Note/CC values, file/schema identifiers, code, diagnostic codes, and concise uppercase metadata. Font family—not a third weight or gratuitous letter spacing—creates the technical distinction.
- Display size is reserved for the active scene, primary cue, critical live values, or a similarly singular operational fact. It is not ordinary page decoration.
- Text zoom to 200% must not clip controls or hide safety actions. Fixed-height chrome truncates noncritical user-authored names with ellipsis and an accessible full-value affordance; instructions, errors, confirmations, and safety labels wrap.

## Copywriting Contract

This consolidation does not rename established product actions. Migrated components preserve domain-specific copy unless it violates the calm, precise brand voice. New shared state components follow these exact patterns:

| Element | Copy |
|---------|------|
| Primary CTA example | `Save Changes` — specific verb plus object; never `Submit`, `OK`, or `Go` when a precise action exists |
| Empty state heading | `No {items} yet` |
| Empty state body | `{Plain explanation}. {Specific next action}.` |
| Loading state | `{Verb in progress}…` such as `Loading fixtures…`; preserve the previous stable projection when safe |
| Error state | `Couldn't {action}. {What remains safe or unchanged}. {Specific retry or recovery path}.` |
| Offline state | `{Service} is offline. Local work continues. GOLC will reconnect automatically.` when that behavior is true |
| Destructive confirmation title | `{Destructive verb} {object}?` |
| Destructive confirmation body | `This {specific impact}. This can't be undone.` only when undo is genuinely unavailable |
| Destructive confirmation buttons | The safe action names the preserved outcome or return path, such as `Keep Mapping`, `Keep Scene`, or `Return to Impact Preview`; the destructive confirmation repeats the exact action, such as `Remove Mapping` |
| Safety actions | Preserve `Blackout`, `Revoke Automation`, and `Stop / Release All`; hold controls use `Hold to {action}` |

Copy rules:

- Use sentence case except terse technical/status labels.
- Use the project lexicon exactly: fixture pool, scene, chase, impact preview, soft takeover, Revoke Automation, Blackout, Art-Net, and universe.
- Do not use exclamation marks, hype, vague success claims, or backend package names as operator-facing information architecture.
- Errors name the failed action and the next step. They do not imply playback/output has stopped unless projected Go state confirms it.
- A loading label does not replace the accessible name of its action. Announce completion/failure through a polite live region when focus does not move.

## Feature CSS Responsibilities

| Feature CSS Modules may own | Feature CSS Modules may not own |
|-----------------------------|---------------------------------|
| Workspace-specific grid/flex topology and named grid areas | Raw palette values, fallback colors, or theme-name selectors |
| Domain-specific track sizing, visualization coordinates, meter/fader/timeline geometry | Font family, public type scale, shared spacing/radius/focus/motion values |
| Bounded overflow policy and responsive rearrangement | Reimplementations of buttons, fields, tabs, badges, dialogs, tooltips, list rows, toolbars, empty/loading/error states |
| Feature-only alignment and ordering of public primitives/patterns | New CSS custom-property declarations outside the approved token/theme layer |
| Monaco/Tiptap/vendor integration selectors that cannot be expressed through component props | Styling native controls to imitate an existing primitive |
| State-dependent layout driven by semantic attributes such as `aria-current`, `aria-expanded`, and `data-state` | Reading `data-theme`/`data-theme-name` or applying palette-specific branches |

Rules:

- A feature may pass layout classes to a primitive only through an explicitly documented `className`/slot API. It may not depend on the primitive's private generated class names or DOM depth.
- Raw numeric values in visual declarations are forbidden when a public token exists. Singular domain geometry must be registered; broad file-level exceptions are invalid.
- CSS custom properties used for runtime geometry (for example a user-resized rail width) must be declared in the design-system sizing contract or registered with their setting site, type/range, fallback, and review condition.
- `color-mix()` is allowed only with semantic color tokens and a documented shared opacity token. Feature-specific literal percentages require registration.
- Structural shadows are not part of Paper/Ink. Modals/popovers use borders, scrims, and the shared overlay treatment; a new shadow requires design review and an exception.

## Interaction State Contract

Every interactive primitive visibly and semantically implements:

| State | Required behavior |
|-------|-------------------|
| Rest | Clear label and affordance; no reliance on hover to discover essential actions |
| Hover | Tap-duration visual cue; no layout movement |
| Active / pressed | Immediate visual acknowledgement; native `:active` or `aria-pressed` where persistent |
| Focus-visible | Two-pixel semantic focus ring with two-pixel offset; never removed without an equally visible replacement |
| Disabled | Native disabled semantics where supported, no dispatch, reduced emphasis, and an adjacent explanation when the reason is not obvious |
| Loading | Prevent duplicate dispatch, retain accessible name, show explicit progress, expose `aria-busy`; do not blank unrelated stable content |
| Selected / current | Signal accent plus border/rail/icon/text or `aria-current`/`aria-selected`; color alone is insufficient |
| Error | Calm message, error icon/text, recovery action, and field association where applicable |

Additional interaction rules:

- UI actions dispatch shared commands and wait for projected Go state before displaying authoritative live/output/safety success. Optimistic styling is limited to local cosmetic/editor state and may not claim a live command succeeded.
- Navigation changes only the projection. Playback and Art-Net continue independently.
- Blackout and Revoke Automation stay visible, prioritized, keyboard reachable, and independent of queued React, script, LLM, or provider work. Visual refactoring cannot merge them or substitute one for the other.
- Hold-to-confirm starts on pointer/key press, shows immediate progress, fires once at the threshold, and cancels cleanly on release, pointer cancellation, focus loss, or Escape.
- Modal focus is trapped, Escape cancels when safe, initial focus defaults to the least destructive action, and focus returns to the invoker.
- Tooltips open on both hover and focus, dismiss on Escape, and never contain task-critical information without an inline equivalent.
- Resizers support arrow-key adjustment and a documented reset gesture. The resulting layout remains within its clamped bounds.
- Motion uses only snap/tap/settle tokens, never blocks input or output, and becomes snap under `prefers-reduced-motion: reduce`.

## Accessibility Contract

- Use native landmarks and elements first: header, nav, main, aside, footer, button, label, input, select, textarea, list, and table where appropriate.
- One logical page/workspace heading is exposed; panels use ordered subordinate headings.
- Keyboard focus order remains global frame → command rail → workspace canvas → inspector → safety cluster, while modal layers temporarily contain focus.
- Icon-only controls have a programmatic name. Decorative icons are `aria-hidden`.
- Form errors are associated with their fields and summarized only when a multi-field submit requires it.
- Loading and background status changes use appropriately scoped polite live regions. Blackout/Revoke failures use assertive announcement without repeatedly interrupting the operator.
- Lists handle zero, one, and many items with correct singular/plural copy and stable focus after insertion/removal.
- Long names truncate only in bounded identity/readout locations and expose the full value through accessible text/title/tooltip. Instructions, diagnostics, evidence, and confirmation impact wrap.
- All actions remain operable without drag; drag/resize interactions have keyboard equivalents.
- Light and dark modes meet WCAG AA contrast. Color is never the only state cue.
- At 200% text zoom and the 900×720 compact acceptance viewport, safety controls, current show/live truth, navigation, and the active task remain reachable without body overflow.

## Exception Registry

The exception manifest is small, machine-readable, reviewed in code review, and validated by the normal design-system check.

Every entry contains:

| Field | Requirement |
|-------|-------------|
| `id` | Stable `DSX-###` identifier |
| `path` | Exact file path; a narrow glob requires explicit justification |
| `rule` | Exact policy rule being excepted |
| `match` | Exact literal, selector, custom property, or AST construct allowed |
| `rationale` | Why no semantic token/primitive/pattern can represent it |
| `source` | Locked decision, vendor constraint, or domain requirement |
| `owner` | Review owner or subsystem |
| `reviewCondition` | Concrete event that forces re-evaluation; “never” is invalid |
| `verification` | Test or visual evidence that bounds the exception |

Initial expected entries:

- Token-independent ErrorBoundary fallback colors, only if the fallback must remain readable before the token stylesheet loads; the exact selectors and literals are listed.
- Vendor-owned Monaco/Tiptap selectors or domain visualization values only when migration proves a semantic API cannot express them; each value is entered separately.

Spacing values cannot be registered as exceptions outside the declared 4px-grid scale. Guided First Show therefore uses the Phase 13 D-03 `8px` gap, while its `210px` rail remains governed as sizing rather than spacing.

Forbidden registry forms:

- Whole-directory or all-CSS exclusions.
- “Legacy,” “temporary,” or “vendor” without a review condition and bounded match.
- Inline disable comments or linter suppression without the matching manifest ID.
- An ignored baseline generated from current violations.

The completed phase begins with no unregistered violation. An exception permits only its exact construct; it does not exempt the containing file from other rules.

## Automated Enforcement

The dependency-light policy checker runs from the frontend package and prints stable rule IDs plus file, line, offending value, and the preferred token/component or exception path.

| Rule | Required detection |
|------|--------------------|
| `DS001 raw-visual-literal` | Hex/rgb/hsl colors, named visual colors, raw typography/spacing/radius/focus/motion/shadow/stacking values outside approved definitions or exact exceptions |
| `DS002 token-declaration-boundary` | CSS custom-property declarations outside approved token/theme/runtime-geometry files |
| `DS003 unknown-token` | Use of an undeclared custom property or a feature-local fallback |
| `DS004 theme-branch` | Theme-name/mode selectors or theme-string branches outside the theme implementation |
| `DS005 duplicate-native-control` | Native controls with feature styling that duplicate a public primitive/pattern; semantic vendor/domain controls require an exception |
| `DS006 duplicate-state-pattern` | Feature-local empty/loading/error/status/button/field/dialog/tab/row/toolbar/focus classes when a shared implementation exists |
| `DS007 export-doc-drift` | Difference between typed public exports, component inventory, guide, and generated token names |
| `DS008 exception-integrity` | Missing fields, broad match, stale path/match, orphan suppression, duplicate ID, or satisfied review condition |
| `DS009 theme-completeness` | Missing semantic token in any supported theme/mode face or undeclared extra theme token |
| `DS010 unsafe-interaction-style` | Removed focus without replacement, color-only state marker, transition outside motion tokens, or hidden safety control at an acceptance viewport |

Enforcement integration:

- `frontend/package.json` exposes one clearly named design-system check and `npm run build` runs it before compilation/tests/bundling.
- The repository's Mage frontend validation path and CI invoke the same package entrypoint; no second policy implementation is maintained.
- Primitive/token contract tests and accessibility interaction tests run in Vitest.
- Playwright visual and geometry suites remain separate browser work but are mandatory in CI for Phase 13 acceptance.
- Checker fixtures include both allowed and forbidden examples for every rule so a broken scanner cannot pass by returning no findings.
- Paths and line diagnostics are deterministic on Windows and CI.
- Generated files are either checked for freshness or generated before checking. Drift fails with the command needed to repair it.
- The checker fails closed on unreadable config/manifest or unsupported syntax; it does not silently skip a file.

## Migration Acceptance

Phase 13 is complete only when:

- Every currently reachable shell surface, workspace, inspector, dialog, editor-adjacent control, and reusable component consumes the unified tokens/primitives/patterns.
- Existing raw visual literals, undeclared custom properties, duplicated common controls, duplicated common states, and focus implementations are migrated or narrowly registered.
- No permanent legacy stylesheet layer, ignored baseline, or split “old/new” component surface remains.

## Visual Verification Contract

### Deterministic fixtures

- Use seeded representative show data with long names, zero/one/many collections, active playback, locked controls, warnings, errors, MIDI pickup, and daemon/provider-offline projections.

| Surface | Required state |

Viewports:

- 1280×720 normal desktop acceptance.
- 900×720 compact desktop acceptance for overflow/reflow and inspector behavior.

In addition to pixel comparison, Playwright asserts:

- no control/text/overlay escapes its own box or viewport;
- application body does not become the workspace scroll container;
- current navigation, live truth, and safety controls remain visible;
- dialogs remain inside the viewport and restore focus;
- light/dark mode changes semantic values without changing layout or component state;
- reduced motion removes animation without hiding progress/state cues.

Every supported alternate theme receives automated token-completeness and contrast tests in light and dark. Representative full-page screenshots are required for default Paper/Ink; alternate-theme screenshots are added only for a palette-specific regression.

## Safety and Authority Invariants

- React and CSS remain projections. No primitive, hook, animation, or theme utility may become a playback clock, Art-Net scheduler, script authority, automation lease authority, or safety authority.
- An action's loading state cannot block the local priority path used by Revoke Automation or Blackout.
- The visual system must distinguish Blackout from Revoke Automation in label, semantics, state, and command path.
- Persistent safety controls are not moved into a menu, dialog-only path, hover-only affordance, or theme-dependent low-contrast treatment.
- A command failure is visible to the operator. The UI does not infer success from pointer/key release or animation completion.
