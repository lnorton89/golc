<task type="auto" tdd="false">
  <name>Round 1: fix three real Test-step failures found in run 30111784838 (all three platforms building, only Test failing)</name>
  <files>cmd/golc-project/main_test.go, internal/artnet/ipc/transport_unix_test.go, internal/delivery/delivery_test.go</files>
  <action>
1. `cmd/golc-project/main_test.go`: the EvalSymlinks fix applied in a prior round (for a different run) was applied unconditionally to both subtests of `TestRunEstablishesResolvedProjectRootBeforeRegistryConstruction`, but only the "absent environment" subtest routes through `os.Getwd()` in production; the "explicit environment" subtest only ever goes through `filepath.Abs`, which never resolves symlinks. Resolving its expectation broke that subtest on macos-latest. Scoped the `EvalSymlinks` call to only the one subtest whose production path actually resolves.
2. `internal/artnet/ipc/transport_unix_test.go`: `shortTestDir()` returned a path without creating it (unlike `t.TempDir()`), so `NewListener`'s single-level `os.Mkdir` (which only ever needs one level under the always-present `/tmp` in production) failed with "no such file or directory" on macOS/Linux. Fixed `shortTestDir()` to create the directory it returns.
3. `internal/delivery/delivery_test.go`: the golden-fixture byte-comparison test is inherently coupled to a windows-amd64 CLI binary path through production code (`graph.go`'s `bootstrap.PlatformExecutablePath` resolves against the real host `runtime.GOOS`/`runtime.GOARCH`), not just the test's own fixture writer — no fixture-side fix can make this pass on macOS/Linux. Skipped the exact byte-comparison subtest on non-Windows hosts with an explanation, consistent with the package's own doc comment scoping the foundation bundle to Windows AMD64.
  </action>

  <files>cmd/golc-project/main_test.go, .gitattributes</files>
  <action>
1. `cmd/golc-project/main_test.go`: `os.Getwd()` on windows-latest reported the 8.3 short-name alias of a path component (`RUNNER~1`) even though `Chdir` was given the long form (`runneradmin`), so the "absent environment" subtest's unresolved observed value never matched its `EvalSymlinks`-resolved expectation. `filepath.EvalSymlinks` also canonicalizes short names on Windows (it walks the real filesystem), so resolved both sides of that one comparison through it instead of just the expected side.
2. `.gitattributes`: `CheckMigration` (`internal/trace/catalog/migrate.go`) compares the committed `.planning/linear-map.json` byte-for-byte against a freshly re-derived canonical encoding, which is always LF-only. Without an `eol=lf` pin, a Windows checkout's `core.autocrlf` conversion made the committed file fail its own drift check even though nothing in the map had actually drifted — the same class of bug already fixed twice earlier in 260723-vj8 for `schemas/**` and `tests/golden/**`.
